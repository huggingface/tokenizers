Added-token matcher comparison

Main's bucket matcher (tk-encode/src/vocab/buckets.rs at d9a5e8af) against branch perf/aho-corasick, which replaces it with the aho-corasick 1.1.5 crate (MatchKind::LeftmostLongest). The same harness is built twice, once per arm. Matches and encoded ids are identical between the arms on every cell, on both hosts.

HF Jobs cpu-performance, AMD EPYC 7R13 (x86_64), pinned to one core. 5 rounds, arms alternating, best of 5 kept. Host 1 job 6ae20e173fb22a235dd41771, host 2 job 6ae20e183fb22a235dd41773. Ratio is aho-corasick ÷ buckets: above 1 means aho-corasick is faster.

Fairness caveat. These are x86 numbers. When a token set starts with 2 or more distinct bytes, the bucket matcher on x86 falls back to a scalar byte loop. The NEON nibble scan only builds on aarch64. Rows marked scalar byte loop therefore compare aho-corasick with that fallback, not with the bucket algorithm. Rows with one first byte use memchr::memmem, which is SIMD on x86, so those comparisons are fair. No ARM numbers yet.

Setup

  • Corpora, 20 MB each. English: FineWeb sample/10BT/000_00000.parquet. Code: the patch column of SWE-bench/SWE-smith-trajectories, deduplicated. Agentic: SWE-smith tool trajectories rendered through each model's own chat template, so the text holds that model's real markers. gpt2 has no template and gets role: content lines. Gemma 3 and surya-ocr-2 reject about half the conversations, which are then rendered as alternating user and assistant turns.
  • Models, from few added tokens to many: openai-community/gpt2, openai/gpt-oss-20b, Qwen/Qwen3-8B, deepseek-ai/DeepSeek-V3, nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B-BF16, datalab-to/surya-ocr-2, and Gemma 3's tokenizer via gaunernst/gemma-3-27b-it-int4-awq (ungated). Revisions are pinned in the job logs.
  • Empty sets. An AhoCorasick built from zero patterns has no prefilter and walks every byte. The branch therefore stores Option<AhoCorasick>. Before that fix, gpt2 and Qwen3 encoded 25–35% slower, because one of their two token sets is empty.
  • Rerun. bench/added-token-matcher/ on the branch: make jobs, then make fetch ID=<job>. The job embeds the branch diff, so nothing needs to be pushed.
