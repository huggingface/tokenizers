# Quicktour

Let's have a quick look at the 🤗 Tokenizers library. The library provides an
implementation of today's most used tokenizers that is both easy to use and
blazing fast.

<Tip warning={true}>

This release is read-only. A tokenizer is loaded from a `tokenizer.json` and
used to encode and decode; it cannot be built from its components, edited,
saved, or trained. See
[`REQUIRED_FOR_V1.md`](https://github.com/huggingface/tokenizers/blob/main/REQUIRED_FOR_V1.md)
for what is deferred and why.

</Tip>

## Loading a tokenizer

Everything starts from a `tokenizer.json`. In Python you can pull one straight
from the Hugging Face Hub, or read one off disk:

<tokenizerslangcontent>
<python>
```python
from tokenizers import Tokenizer

tokenizer = Tokenizer.from_pretrained("bert-base-uncased")
# or, from a local file:
tokenizer = Tokenizer.from_file("tokenizer.json")
```
</python>
<rust>
```rust
let tokenizer = tokenizers::from_json_file("tokenizer.json")?;
```
</rust>
<node>
```js
const { PipelineTokenizer } = require('tokenizers')

const tokenizer = PipelineTokenizer.fromFile('tokenizer.json')
```
</node>
</tokenizerslangcontent>

`from_pretrained` takes the usual Hub arguments — `revision` to pin a commit,
branch or tag, and `token` to reach a private or gated repository:

<tokenizerslangcontent>
<python>
```python
tokenizer = Tokenizer.from_pretrained("my-org/my-model", revision="v1.0", token=True)
```
</python>
</tokenizerslangcontent>

## Encoding

Encode a text with the `encode` method:

<tokenizerslangcontent>
<python>
```python
output = tokenizer.encode("Hello, y'all! How are you 😁 ?")
```
</python>
<rust>
```rust
use tk_encode::pipeline::EncodeOptions;

let output = tokenizer
    .encode("Hello, y'all! How are you 😁 ?", &EncodeOptions::default())
    .wait()?;
```
</rust>
<node>
```js
// Returns a Uint32Array of ids, not an object: a JS Array costs one napi value
// per token, which on token-dense input is 13x the encode itself.
const ids = tokenizer.encode("Hello, y'all! How are you 😁 ?")
```
</node>
</tokenizerslangcontent>

In Python and Rust this returns an `Encoding`, carrying everything your model
needs. The `ids` are the index of each token in the tokenizer's vocabulary:

<tokenizerslangcontent>
<python>
```python
print(output.ids)
print(output.type_ids)
print(output.attention_mask)
```
</python>
<rust>
```rust
let encoding = &output[0];
println!("{:?}", encoding.ids().iter().map(|t| t.id()).collect::<Vec<_>>());
println!("{:?}", encoding.type_ids());
println!("{:?}", encoding.attention_mask());
```
</rust>
</tokenizerslangcontent>

Python also exposes each of these as a numpy array — `ids_array`,
`type_ids_array` and `attention_mask_array` — which is what you want when the
next stop is a tensor.

By default the tokenizer's post-processor adds the special tokens its config
defines, such as `[CLS]` and `[SEP]`. Pass `add_special_tokens=False` to skip
that, and `encode_special_tokens=True` to send special tokens written in the
text through the model rather than matching them in the added vocabulary:

<tokenizerslangcontent>
<python>
```python
output = tokenizer.encode("Hello, y'all!", add_special_tokens=False)
```
</python>
<rust>
```rust
let output = tokenizer
    .encode("Hello, y'all!", &EncodeOptions::no_specials())
    .wait()?;
```
</rust>
<node>
```js
const ids = tokenizer.encode("Hello, y'all!", { addSpecialTokens: false })
```
</node>
</tokenizerslangcontent>

## Decoding

`decode` turns ids back into text, and `decode_tokens` gives you the individual
token strings without running the decoder:

<tokenizerslangcontent>
<python>
```python
tokenizer.decode(output)
# "hello, y'all!"

tokenizer.decode_tokens(output)
# ["[CLS]", "hello", ",", "y", "'", "all", "!", "[SEP]"]
```
</python>
<rust>
```rust
let ids: Vec<u32> = encoding.ids().iter().map(|t| t.id()).collect();
println!("{}", tokenizer.decode(&ids, true)?);
println!("{:?}", tokenizer.decode_tokens(&ids, false));
```
</rust>
<node>
The Node binding encodes only; it has no decode method.
</node>
</tokenizerslangcontent>

`Tokenizer.tokenize` is shorthand for `decode_tokens(encode(text))` when you
only care about the token strings:

<tokenizerslangcontent>
<python>
```python
tokenizer.tokenize("Hello, y'all!")
# ["[CLS]", "hello", ",", "y", "'", "all", "!", "[SEP]"]
```
</python>
</tokenizerslangcontent>

## Encoding a batch

<tokenizerslangcontent>
<python>
```python
output = tokenizer.encode_batch(["Hello, y'all!", "How are you 😁 ?"])
print(output[1].ids)
```
</python>
<rust>
```rust
let output = tokenizer
    .encode(vec!["Hello, y'all!", "How are you 😁 ?"], &EncodeOptions::default())
    .wait()?;
```
</rust>
<node>
The Node binding encodes one text per call. For a tight loop, `encodeBytesInto`
writes into a `Uint32Array` you own, avoiding both the JS string copy and a
fresh `ArrayBuffer` per call:

```js
const out = new Uint32Array(512)
const n = tokenizer.encodeBytesInto(Buffer.from("Hello, y'all!"), out)
// the first n entries of `out` are the ids
```
</node>
</tokenizerslangcontent>

## Padding and truncation

Padding brings every encoding in a batch up to the same length — by default the
length of the longest item. Truncation caps it. Both can be set once on the
tokenizer, or per call:

<tokenizerslangcontent>
<python>
```python
from tokenizers import Padding, Truncation

tokenizer.padding = Padding(pad_id=0, pad_token="[PAD]")
tokenizer.truncation = Truncation(max_length=512)

# or for one call only, overriding whatever is configured:
output = tokenizer.encode_batch(
    ["Hello, y'all!", "How are you 😁 ?"],
    padding=Padding(length=16),
    truncation=None,
)
```
</python>
<rust>
```rust
use tk_encode::pipeline::Override;
use tk_encode::utils::padding::PaddingParams;

let options = EncodeOptions {
    padding: Override::With(PaddingParams {
        pad_id: 0,
        pad_token: "[PAD]".to_string(),
        ..PaddingParams::default()
    }),
    ..EncodeOptions::default()
};
```
</rust>
<node>
```js
const ids = tokenizer.encode("Hello, y'all!", {
  padding: { padId: 0, padToken: '[PAD]', length: 16 },
  truncation: { maxLength: 512 },
})
```
</node>
</tokenizerslangcontent>

Padding shows up in the `attention_mask`, which is `0` at every padded
position:

<tokenizerslangcontent>
<python>
```python
output = tokenizer.encode_batch(["Hello, y'all!", "Hi"])
print(output[1].attention_mask)
```
</python>
</tokenizerslangcontent>

Set either property to `None` to switch it off:

<tokenizerslangcontent>
<python>
```python
tokenizer.padding = None
tokenizer.truncation = None
```
</python>
</tokenizerslangcontent>
